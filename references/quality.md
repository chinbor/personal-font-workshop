# 验收与发布

## 自动检查 ≠ 可读性检查

| 层级 | 检查与证据 |
|---|---|
| 结构 | 重开 TTF；cmap 覆盖约定字符；SPACE/NBSP 为空；outline validation；无意外零宽/混合宽度；内部名称正确；垂直范围不超行框 |
| 渲染 | 用输出的真实字体渲染整套试字，不用替代字体或生成图冒充；检查缺字、镜像、孔洞、粗细、基线和裁切 |
| 使用 | 在用户指定软件与常用字号实测；核对光标、选区、当前行背景及下伸笔画；记录版本身份和软件设置，保存截图或用户反馈 |

推荐 12、14、16、20 px 对比，但采用用户的真实环境优先。只测大海报不能证明正文或编程可用。用同一段内容、同字号、同缩放对照版本。

## 小字号排查顺序

1. **确认实际加载**：内部 family 是否匹配，是否需要重启应用，是否仍命中旧缓存，是否合成粗体，缺字是否走了 fallback。只改文件名不改变字体内部名称。
2. **字面与笔画**：字腔堵塞、曲线偏重、交叉处发黑？调整源轮廓和比例。机械地缩小字号或全体内缩不能替代逐类字形检查。
3. **间距**：检查 advance、左右留白、实际字面宽度。所谓“空格太宽”可能是 Tab、多个空格或编辑器 letterSpacing，而不只是 U+0020。
4. **等宽约束**：普通字符、数字、标点、空格及加入的 NBSP 都按同一 advance；视觉空白过大时整体评估字面/占位，不能只把空格变窄。
5. **栅格化**：在轮廓已经合理时比较无 hinting 与自动 hinting；不同系统有不同渲染，不默认自动提示必然更好。

如果症状是字面偏下、光标异常长或上下裁切，走 [行高诊断](metrics.md)，不要先移动所有轮廓或仅修改编辑器行距来掩盖问题。

试字组：

```text
ABCDEFGHIJKLMNOPQRSTUVWXYZ
abcdefghijklmnopqrstuvwxyz
0123456789
Il1|  O0o  rn m  2Z  5S  6G  8B
{} [] () <> / \ :; ,. '" `~ +-*/% =! &|^_
const count = 10;
if (value != null) { return value; }
A A  A   A
```

检查成对括号、引号、反斜杠、反引号、下划线的位置，不只看英文单词。NBSP 是不允许在该处自动换行的空格，不是 Tab，也不是零宽空格；在等宽字体中它保持与普通空格一致的宽度。

## 仅改名时

保留输入文件，创建新输出。更新 family/subfamily/full/PostScript/unique ID/version 等相关 name 记录和字重标记；检查名称不混入旧测试名。对原有字形记录轮廓与 advance 的签名，导出重开后对照；如发生差异，不宣称“仅改名”。NBSP 新增与既有字形修改分别记录。

## 安装与实际测试

先交付文件，只有用户要求安装时才操作系统字体目录。Windows 通常可双击 TTF 安装；macOS 使用字体册；Linux 使用用户字体目录并刷新缓存，按实际系统确认。不要未经授权卸载或覆盖旧字体。

VS Code 中填真实的内部 family 名，可从 `editor.fontFamily` 设置；初测建议正常字重、letterSpacing=0、关闭连字。添加合适的回退字体。默认英文首版不含中文、图标和编程连字，不能声称覆盖这些内容。

Cursor 与 VS Code 要分别读取其实际配置；用户、工作区、配置档及语言设置可能互相覆盖。记录 `fontSize`、`lineHeight`（未设置也要记录）、`fontWeight`、`letterSpacing`、缩放与系统显示比例。不要把某一环境的 16 字号/22 行高变成固定标准。

### 编辑器验收记录

每个候选版本保留一条记录：

- 交付文件：路径、SHA-256、内部 family/PostScript/version。
- 安装文件：可定位时记录路径、SHA-256、与交付文件是否一致；未定位写“未确认”。文件相同不等于已证明应用实际加载它。
- 应用环境：编辑器及版本、有效字体配置、字号、行高、字重、字距、缩放；是否已重启，是否有回退字符。
- 图像证据：截图/用户反馈，覆盖的字符与字号；普通光标、当前行背景、文字选区、`Hxnpgjy|()[]{},;_` 的裁切与基线。
- 结果与回退：通过/待验证的具体项目，原字体和原设置的位置。只按截图已覆盖的范围下结论。

光标表示行框而非每个字母的外接矩形。小写字母比光标矮、降部占用基线下空间是正常的；目标是整体位置自然、不贴底、不裁切，不是让每个字都撑满光标。

## 交付清单

- 设计简报、源轮廓、字符映射与参数；可编辑 SFD、安装用 TTF。
- 自动结构报告；整套字符试字和小字号对照；目标软件实际测试状态。
- 使用的内部家族名、版本、字符覆盖、已知限制与安装说明。
- 素材/参考/第三方字体来源及已知许可，未确认项明确标记。原创设计过程不等于法律意见，不保证绝无相似字体或版权风险。

交付标签使用“试验版”“结构检查通过、待实测”或“指定环境实测通过”。不要把不同层级合并成笼统的“全部没问题”。
